## Purpose

This directory contains the **canonical JSON Schema definitions (v1.0)** for the entire experiment pipeline. These schemas are **frozen** and production-stable, serving as the authoritative data contracts for configs, results, metrics, and analysis.

**Critical**: These schemas are the **source of truth**. All Pydantic models in `src/engine/models/` must remain synchronized with these schemas.

## Structure

```
schemas/
├── v1/
│   ├── schema_index.json         # Schema registry and dependency map
│   ├── core/                     # Reusable building blocks
│   │   ├── experiment_spec.schema.json
│   │   ├── provenance.schema.json
│   │   └── structure_metrics.schema.json
│   ├── execution/                # Runtime results
│   │   ├── experiment_result.schema.json
│   │   └── sweep_manifest.schema.json
│   └── analysis/                 # Aggregated analysis
│       └── analysis_result.schema.json
├── examples/
│   └── v1/
│       ├── valid/               # Reference valid examples
│       └── invalid/             # Edge cases and validation tests
├── README.md                     # Human-readable overview
└── CHANGELOG.md                  # Schema version history
```

## Schema Versioning

- **Current Version**: `1.0` (frozen as of 2025-08-16)
- **Breaking changes** → Major version bump (e.g., `2.0`)
- **Non-breaking additions** → Minor version bump (e.g., `1.1`)
- **All schemas versioned together** — No independent versioning

## Local Boundaries

### Allowed Operations

- **Read schemas** for validation and reference
- **Add examples** to `examples/v1/valid/` or `examples/v1/invalid/`
- **Update CHANGELOG.md** when schemas change
- **Validate JSON** against schemas using JSON Schema validators

### Forbidden Operations

- **Modify v1.0 schemas** without version bump and team approval
- **Delete or rename schemas** without updating `schema_index.json`
- **Add new schemas** without following the versioning protocol
- **Create schema variants** outside the versioned directory structure
- **Bypass schema validation** in code that generates JSON artifacts

## Do Not

- **Edit schemas directly** without understanding breaking vs. non-breaking changes
- **Create duplicate schemas** — Reuse via `$ref` instead
- **Skip examples** — Every schema change needs valid/invalid examples
- **Ignore provenance** — All changes must be documented in `CHANGELOG.md`
- **Modify frozen versions** — Create a new version instead
- **Mix versions** — All schemas in a version folder must have the same version number

## Always

- **Use `$ref`** for shared definitions (avoid duplication)
- **Include `"$schema"`** declaration in every schema file
- **Provide examples** in `examples/` for every schema
- **Document breaking changes** clearly in `CHANGELOG.md`
- **Update `schema_index.json`** when adding/removing schemas
- **Test with validators** before committing schema changes
- **Sync Pydantic models** in `src/engine/models/` after schema changes

## Schema Dependency Flow

```
experiment_spec ──┐
                  ├──> experiment_result ──> analysis_result
structure_metrics ┘         ↑
                           │
sweep_manifest ────────────┘
```

**Key Rules**:
- `core/` schemas are **building blocks** (referenced by others)
- `execution/` schemas **embed** core schemas as snapshots
- `analysis/` schemas **aggregate** execution results

## Key Patterns

### Referencing Shared Schemas

```json
{
  "type": "object",
  "properties": {
    "spec": {
      "$ref": "../core/experiment_spec.schema.json"
    }
  }
}
```

### Embedding vs. Linking

- **Embed** (`$ref` inline) when capturing a snapshot (e.g., config at runtime)
- **Link** (via ID/hash) when referencing mutable entities

### Validation Requirements

All JSON artifacts generated by the framework must validate against these schemas:

```bash
# Validate using jsonschema (Python)
jsonschema -i data/result.json schemas/v1/execution/experiment_result.schema.json
```

## Schema Responsibilities

### `core/experiment_spec.schema.json`

- **Purpose**: Define experiment intent (state type, qubits, noise, shots)
- **Referenced by**: `experiment_result`, `sweep_manifest`
- **Versioning**: Never modify; create new version if needed

### `core/structure_metrics.schema.json`

- **Purpose**: Standardized decoherence metrics (EEC, PCR, Structure Score)
- **Referenced by**: `experiment_result`
- **Requirements**: All metrics include value + 95% CI + validation status

### `core/provenance.schema.json`

- **Purpose**: Track reproducibility (config hash, commit, backend, timestamp)
- **Referenced by**: `experiment_result`
- **Critical**: Never skip or partial-populate provenance fields

### `execution/experiment_result.schema.json`

- **Purpose**: Capture single experiment run outcome
- **Embeds**: `experiment_spec`, `structure_metrics`, `provenance`
- **Immutable**: Results are write-once; never modify after creation

### `execution/sweep_manifest.schema.json`

- **Purpose**: Define parameter sweep configuration
- **Embeds**: Base `experiment_spec` + parameter ranges
- **Usage**: Input to sweep driver in `src/engine/sweep_driver.py`

### `analysis/analysis_result.schema.json`

- **Purpose**: Aggregate results and conclusions
- **References**: `sweep_manifest`, array of `experiment_result`
- **Usage**: Final output of analysis pipelines

## Validation Workflow

1. **Schema Design** → Create/modify schema in `v1/`
2. **Examples** → Add valid + invalid examples to `examples/v1/`
3. **Validation** → Test examples against schema
4. **Pydantic Sync** → Update models in `src/engine/models/`
5. **Documentation** → Update `README.md` and `CHANGELOG.md`
6. **Version Bump** → If breaking change, bump major version

## Integration with Code

### Pydantic Models Must Match

```python

class ExperimentConfig(BaseModel):
    """Must match schemas/v1/core/experiment_spec.schema.json"""
    num_qubits: int
    state_type: str
    # ... fields match schema exactly
```
